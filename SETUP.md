# Setup Guide

Getting agents42 running from scratch on your own machine, so you can test the WhatsApp booking
flow independently of whoever built it. If you just need to run the already-set-up stack day to
day, see [OPERATION.md](OPERATION.md) instead - this doc is for a fresh machine/person.

## Files someone on the team needs to send you privately

Everything else in this guide you can do yourself. Only one file is a shared secret:

| File | What it is | Why it's not in git |
|---|---|---|
| `credentials/calendar_credentials.json` | The Google OAuth client secret for the shared `agent42-scheduler` Google Cloud project | It's a project credential - low risk on its own (a "Desktop app" client can't access anything without someone completing a browser consent flow), but still send it over a private channel (DM, not a public team channel), not email/commit it. |

**Do not ask for or send:**
- `credentials/calendar_token.json` - this is generated by *your own* browser OAuth consent in
  step 3 below. It's tied to whoever approved it; sharing it means sharing a live, working
  credential rather than each person having their own. Generate your own.
- `.env` - copy it from `.env.example` yourself (see step 1). Nothing in it is a real secret for
  local dev - Postgres only runs in your own Docker network, and the LLM provider key lives in
  OpenClaw's own config, not here.

**Separately, ask whoever has it** to add your Google account's email as a **test user** on the
Google Cloud OAuth consent screen (Google Cloud Console → APIs & Services → OAuth consent screen →
Test users). Without this you'll get `Error 403: access_denied` in step 3 - the app is in
"Testing" publishing status, so only explicitly-added accounts can authorize it.

If your team has the hackathon's own AWS Bedrock gateway key (sent by the organiser via email),
that's a separate thing entirely - it configures OpenClaw's model provider (step 4), not this
repo. Get it from whoever on your team received that email if you're using it instead of a
personal API key.

## Prerequisites

- Docker + Docker Compose
- Python 3.12+
- git, and access to clone this repo
- A phone with WhatsApp, to link as the test number (your own, or a spare - see OPERATION.md's
  safety note before linking a number anyone else can message)
- Node.js (installed below via nvm, for OpenClaw)

## 1. Clone and check out the branch

```bash
git clone <repo-url> agents42
cd agents42
git checkout feat/groomer-vertical-slice   # or main, once merged
cp .env.example .env
```

Open `.env` and check `AGENTS42_API_BASE_URL` and the Docker port mapping in
`docker-compose.yml` (`"8090:8000"` by default) - **change both together** if port 8090 is
already taken on your machine (common culprits: Portainer, another dev server). They must match.

## 2. Start the backend

```bash
docker compose up -d --build
curl http://localhost:8090/health   # {"status":"ok"} - adjust port if you changed it above
```

This runs FastAPI + PostgreSQL only. OpenClaw is deliberately not in this Compose file - see
DEVELOPMENT.md for why - so it's installed natively in step 4.

## 3. Connect Google Calendar

1. Get `credentials/calendar_credentials.json` from a teammate (see the table above) and place
   it at that exact path in the repo root.
2. Confirm you've been added as a test user (see above) - ask if you haven't.
3. Run the one-time browser OAuth flow, from the repo root:
   ```bash
   python3 -m venv app/.venv && source app/.venv/bin/activate
   pip install -e './app[dev]'
   export PYTHONPATH=app/src
   python -m agents42.integrations.google_calendar_auth
   ```
4. It prints a URL (or opens your browser directly) - sign in with **whichever Google account you
   want tested against** (by default, `businesses/demo-groomer.yaml` uses `calendar_id: primary`,
   meaning your own primary calendar). Approve the "unverified app" warning (Advanced -> Go to
   agent42-scheduler) and the permission screen (this requests full read/write Calendar access,
   since the agent both checks availability and creates bookings).
5. This writes `credentials/calendar_token.json` - yours alone, don't share it.
6. Restart the backend so it picks up the new file: `docker compose restart app`.

Verify:
```bash
curl -X POST http://localhost:8090/availability/search \
  -H 'Content-Type: application/json' \
  -d '{"business_id":"demo-groomer","service":"full_grooming","date":"2026-09-25"}'
```
You should get back real `slots`, not a 502.

**Want everyone on the team testing against the same shared calendar instead of their own?**
Create one dedicated Google Calendar, share it with each teammate's Google account ("Make changes
to events" permission), and set `calendar_id` in `businesses/demo-groomer.yaml` to that calendar's
ID (Calendar settings -> "Integrate calendar" -> Calendar ID) instead of `primary`. Everyone still
runs their own OAuth consent in step 3 above - only the target calendar becomes shared.

## 4. Install OpenClaw, connect an LLM provider, connect WhatsApp

```bash
curl -fsSL https://opencode.ai/install | bash
source ~/.bashrc

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.7/install.sh | bash
\. "$HOME/.nvm/nvm.sh"
nvm install 24

curl -fsSL https://openclaw.ai/install.sh | bash
openclaw onboard
```

During onboarding (or later via `openclaw onboard` again / editing `~/.openclaw/openclaw.json`),
configure a model provider - either your own API key for a cheap tool-capable model, or the
hackathon's shared AWS Bedrock gateway key from your team.

**Install the skill and point it at your backend:**
```bash
export AGENTS42_API_BASE_URL=http://localhost:8090   # match step 2's port
openclaw skills install ./openclaw/workspace/skills/front-desk --as front-desk --force
```

If OpenClaw runs as a background service (it does by default on Linux, via systemd), that
`export` only affects your current shell - the service needs it set separately:
```bash
mkdir -p ~/.config/systemd/user/openclaw-gateway.service.d
cat > ~/.config/systemd/user/openclaw-gateway.service.d/agents42.conf <<'EOF'
[Service]
Environment=AGENTS42_API_BASE_URL=http://localhost:8090
EOF
systemctl --user daemon-reload
systemctl --user restart openclaw-gateway
```
(macOS: same idea via `launchctl setenv` or editing the launchd plist; Windows: via the scheduled
task's environment - see `openclaw daemon --help`.)

**Link WhatsApp:**
```bash
openclaw channels add --channel whatsapp
```
Scan the printed QR code from your phone: WhatsApp -> Linked Devices -> Link a Device.

**Before testing with a real number**, restrict who can message it - see OPERATION.md's safety
note. This matters more on a shared team setup than solo, since anyone with the number can trigger
real bookings on whatever calendar you connected in step 3.

## 5. Verify the whole thing works

```bash
openclaw agent -m "Hi, I'd like to book a full grooming appointment for tomorrow afternoon."
```

This runs a one-off turn through your real gateway/skill without needing to send a WhatsApp
message. Expect either real slots + a completed booking, or a clear "I can't verify that" /
escalation message if something upstream (Calendar, backend) isn't reachable yet - never a
confident-sounding made-up answer. If you get the latter, see OPERATION.md's troubleshooting
section.

Then try it for real: message the linked WhatsApp number from another phone.

## Uninstalling / starting over

```bash
docker compose down -v        # drops the local Postgres data too
openclaw uninstall             # removes OpenClaw's gateway service + local state; CLI remains
```
